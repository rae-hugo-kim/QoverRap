## 1. 청구항 오참조

**금지 패턴**: 종속 청구항이 (a) 자기와 같거나 큰 번호의 청구항을 인용하거나, (b) 존재하지 않는 청구항을 인용.

**예** (잘못):
```
[청구항 3] 제2항 또는 제3항, 제4항에 있어서, ...
                    ^^^^   ^^^^
                    자기   존재하지 않을 수 있음
```

**대응**: 종속 청구항 N 은 1 ~ N-1 의 실제 존재하는 청구항만 인용.

---

## 2. 중복 다중참조

### 지원하는 인용 유형

| 유형 | 예시 |
|---|---|
| 불특정 연속 다중항 (이전 모든 청구항) | `위 항들`, `위의 항들`, `상기의 항들`, `선행하는 항들` |
| 명시적 연속 다중항 (n ~ m 모두) | `제n항 내지 제m항` |
| 명시적 개별항 (또는/및/`,` 분산) | `제n항`, `청구항m` |

### 지원하는 인용항 기재 형식

| 형식 | 예시 |
|---|---|
| 제n항 | `제10항`, `제 11항`, `제12 항`, `제 13 항`, `14항`, `15 항` |
| 청구항m | `청구항14`, `청구항 15` |

### ❌ 지원하지 않는 형식

```
청구항1, 2, 3에 대하여 ...   ← "2, 3" 미지원 (각각 "청구항 2", "청구항 3" 으로 풀어 써야)
1, 2, 3, 4항에 대하여 ...    ← "1, 2, 3" 미지원 (각각 "1항", "2항", "3항" 으로 풀어 써야)
```

**적용 규칙**: 모든 인용은 "제n항" 또는 "청구항 m" 의 **완전 형태** 로 작성. 단축 표기 (숫자만, 또는 첫 인용만 풀어 쓰는 형식) 금지.

## 3. 불명확한 표현

청구항 내에 다음 단어 사용 시 점검 경고.

### 금지어 35종

| 카테고리 | 단어 |
|---|---|
| 선택/조건 모호 | `소망에 따라`, `필요에 따라`, `특히`, `예를 들어`, `예를 들면`, `및/또는`, `을 제외하고`, `이 아닌` |
| 정도 모호 | `주로`, `주성분으로`, `많은`, `높은`, `대부분의`, `거의`, `대략`, `약 `, `최적` |
| 적합성 모호 | `적합한`, `적합하게`, `적량의`, `적당한`, `적당하게`, `적절하게`, `적절한`, `바람직하게` |
| 과장 표현 | `울트라`, `초특급`, `매우`, `슈퍼` |
| 카테고리 한정 | `방법` (실용신안일 경우에만) |

**적용 규칙**: 위 단어가 청구항 본문에 등장하면 객관적/정량적 표현으로 대체.

## 4. 종결어 불일치

**판정 기준**:
- 공백/탭/새 줄로 구분되는 **마지막 한 단어**가 기준
- 마지막 단어 뒤의 공백/탭/`,` 는 무시

**적용**: 인용되는 독립항의 마지막 단어와, 인용하는 종속항의 마지막 단어가 일치해야 함.

### 예시

| 청구항 | 마지막 단어 | KEAPS 판정 |
|---|---|---|
| 청1 (방법): `...단일 QR 페이로드 생성 방법.` | `방법` | — |
| 청3 (방법 종속): `...단일 QR 페이로드 생성 방법.` | `방법` | ✓ 일치 |
| 청10 (CRM): `...컴퓨터 판독 가능 저장 매체.` | `매체` | ✗ 불일치 (방법 ↔ 매체) |

### ⚠ 카테고리 변환 함정

CRM 청구항이 방법 청구항을 인용하면 (방법 → 매체) **항상 불일치** 로 판정됨.

**해결책**:
- (a) CRM 을 **독립항** 으로 작성 (`청구항 N` 인용 텍스트 제거 → 본문 inline 요약)
- (b) CRM 의 마지막 단어를 인용 청구항과 같이 (예: "...컴퓨터 판독 가능 저장 매체에 의해 수행되는 방법.") — 비표준, 비권장

**적용 규칙**: 독립항 ↔ 종속항 간 카테고리 동일 유지. 카테고리 변환은 독립항으로.

---

## 5. 택일어 미사용

**금지 패턴**: 다중 인용에 "어느" 누락.

**예** (잘못):
```
제1항 및 제2항의 방법에 있어서, ...
제3항 내지 제4항에 있어서, ...
```

**예** (올바름):
```
제1항 및 제2항 중 어느 한 항에 있어서, ...
제3항 내지 제4항 중 어느 한 항에 있어서, ...
```

**적용 규칙**: 다중 인용 시 항상 `중 어느 한 항` 추가.

---

## 6. 상기 인용 없음

**판정 기준**: "상기 X" 의 `X` 가 (a) 같은 청구항 내 앞 부분 또는 (b) 인용항 (종속 사슬) 의 본문에 **구조적으로** 존재해야 함.

### 점검 시 제외 요소

| 제외 카테고리 | 단어 |
|---|---|
| 관형어 | `각`, `각각`, `각각의`, `다른`, `선택된` |
| 조사 | `로부터`, `에서`, `들은`, `들의`, `등은`, `등의`, `부터`, `으로`, `로`, `은`, `는`, `이`, `가`, `을`, `를`, `와`, `과`, `의`, `에`, `된`, `등` |
| 문장부호 | `,`, `.`, `:`, `;` |

### 시각화 표시 (KEAPS UI)

| 상태 | 색상 |
|---|---|
| antecedent 존재 | 🟢 녹색 |
| antecedent 부재 | 🔴 빨강 (수정 필요) |
| `상기` 뒤 공백 없이 바로 구문 | ⚠ 경고 표시 (점검은 수행) |

### 적용 규칙

- "상기 X" 작성 전에 X 가 어디에 정의되었는지 확인 (현재 청구항 본문 또는 종속 사슬)
- 종속 사슬이 끊긴 경우 (예: CRM 독립항, 시스템 독립항) — "상기" 대신 본문에서 X 를 직접 정의
- antecedent 가 정확히 같은 단어여야 함 (변형 표현은 KEAPS 가 동일성 인식 못 함)

## 작업 시 체크리스트 (claim 작성/수정 직후)

- [ ] 종속 인용 번호 < 자기 청구항 번호 (오참조 방지)
- [ ] 다중 인용 시 `중 어느 한 항` 포함 (택일어)
- [ ] 인용 형식 = `제n항` 또는 `청구항 m` 의 완전 형태
- [ ] 마지막 단어 = 인용 청구항과 동일 (카테고리 일치)
- [ ] 카테고리 변환 (CRM 등) → 독립항으로 재작성
- [ ] 모든 `상기 X` → X 가 같은 청구항 내 앞 또는 종속 사슬에 정의되었는지 확인
- [ ] 불명확 35종 단어 미사용 (grep 권장)
- [ ] 다른 청구항 본문을 명시 인용하지 말 것 (자기 parent 자체 인용 외) — KEAPS 가 다중참조로 오인 가능
